mcp-gitreview

A personal project — interview explainer cheat sheet

One-Liner (say this first)

"I built an MCP server in Go that lets AI assistants like Claude query GitHub repositories using natural language — things like listing commits, branches, PRs, and repo stats — without the AI needing direct access to git or the GitHub API."

The Problem it Solves

AI chat assistants are powerful but have no built-in awareness of your GitHub repos. You'd have to copy-paste commit logs or PR lists manually into the chat. This project plugs that gap by giving the AI a structured set of tools it can call autonomously to fetch live repo data on demand.

How it Works — End to End

1
You run the binary. It starts an MCP server over stdio — the standard transport Claude Desktop uses to talk to local tools.
2
You ask Claude in plain English. e.g. "Show me the open PRs in kubernetes/kubernetes"
3
Claude calls set_github_repository first (if no repo is set). The server stores the repo name in a thread-safe in-memory context.
4
Claude calls the relevant tool, e.g. list_pull_requests. The tool handler reads the repo from context, makes a live GitHub REST API call, formats the result as plain text.
5
The formatted string is returned to Claude, which presents it to you. No UI needed — the LLM handles the presentation layer.

Exposed MCP Tools

set_github_repositorySet/switch the active repo
set_github_tokenAdd a PAT for private repos (auto-expires in 1h)
list_commitsLast 10 commits with SHA + author
list_branchesAll branches
get_latest_commit_messageMost recent commit message
get_repository_detailsStars, forks, open issues, description
list_pull_requestsOpen PRs with author + URL

Code Structure — 3 Layers

PackageResponsibilityKey Design Point
internal/github GitHub REST API client — HTTP requests, auth header injection, JSON decoding Token is a function (TokenProvider), not a value — so it's always evaluated fresh (catches expiry)
internal/server Holds session state: active repo + token sync.RWMutex for concurrency safety; token has a TTL (expires after 1 hour)
internal/tools Registers each MCP tool with its handler All tools share a requireRepo helper — fail fast with a clear message if no repo is set

Design Decisions Worth Mentioning

Why stdio transport?
MCP over stdio is the standard for local tools in Claude Desktop — no network port, no auth complexity, just a long-lived process communicating via stdin/stdout.
Why store state in a server-side context instead of passing repo per call?
Better UX — the LLM only needs to set the repo once per session. It mirrors how a human "switches context" to a repo and then runs multiple queries against it.
Why is the token a function (TokenProvider) instead of a plain string?
Lazy evaluation — the token is checked at call time, so if it has expired between when it was set and when a tool runs, it returns empty and the API call fails gracefully rather than silently using a stale token.
Why no default repo?
Intentional — forces the LLM to ask the user which repo they want, rather than silently operating on a wrong default.
